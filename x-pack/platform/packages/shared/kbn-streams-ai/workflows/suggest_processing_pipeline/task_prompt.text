Analyze this data stream and build a post-processing pipeline. Use an **iterative eval/dev loop**: inspect fields, design, simulate, fix errors, repeat.

## Your Workflow

1. **Analyze** the dataset analysis below to understand the data structure
2. **Inspect** each field in the dataset analysis for issues:
   - `(unmapped)` fields likely need type conversions via `convert` processors
   - Temporary fields from parsing (e.g., `attributes.custom.*`) should be removed after use
   - Verify field *values* match schema semantics — not just that the field exists
   - Non-ISO date strings need `date` processors; numeric strings need `convert`
3. **Design** a pipeline addressing the issues found
4. **Call `simulate_pipeline`** to test it against sample data
5. **Read the errors** carefully — check the `processors` section for per-processor failure rates to identify exactly which processor is broken
6. **Repeat** steps 4-5 until simulation passes
7. **Call `commit_pipeline`** when done

**Expect multiple iterations.** The first attempt rarely works perfectly. Read error messages — they include processor IDs so you know exactly which processor to fix.

**Less is more.** When fixing errors, simplify rather than add complexity. Remove problematic processors instead of adding workarounds.

## Tools

- **`simulate_pipeline(pipeline)`** - Runs your pipeline against the sample documents shown in the dataset analysis. Returns per-processor metrics, errors, and overall validation. The response includes a `processors` section showing which specific processors failed.
- **`commit_pipeline(message)`** - Finalize when simulation passes.
